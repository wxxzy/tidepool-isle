# 02 · 数据驱动与纯逻辑状态机

> 目标：把玩法写成"没有节点也能跑"的状态机，并且数值全部外置到 JSON。
> 预计 30 分钟 · 前置：第 01 篇

---

## 为什么要拆成"纯逻辑"

钓鱼流程很啰嗦：蓄力 → 抛竿飞行 → 落水 → 静默 → 轻点 → 咬钩 → 收线拉扯 → 上鱼/断线/脱钩。

如果这段逻辑写在一个继承 `Node3D` 的控制器里，你会发现：

- 想测"咬钩窗口只有 0.4 秒，慢了会怎样"必须开窗口、等 3 秒、手动点鼠标
- 想测"断线"必须刻意把张力拉满
- 一次全路径回归要花五分钟，还得盯着屏幕

所以我把它拆成两个文件：

| 文件 | 类型 | 依赖 | 能测什么 |
|---|---|---|---|
| `fishing_core.gd` | `RefCounted` | **无**（纯数据 + 信号） | 全状态机、概率、数值 |
| `fishing_controller.gd` | `Node3D` | 场景树 | 浮漂、钓线、音效、HUD |

核心是 364 行纯逻辑，控制器只负责"把状态翻译成画面和声音"。

## 步骤 1：状态机长什么样

```gdscript
enum State { IDLE, CHARGING, CASTING, WAITING, BITE, REELING }
```

六个状态，不多不少。设计时我砍掉了很多想法（"收杆动画态""鱼上钩后挣扎前的迟疑态"），
因为它们都能塞进现有状态的一个计时器里。**状态爆炸是这类游戏最常见的过度设计。**

事件用信号往外抛，控制器订阅：

```gdscript
signal state_changed(new_state: int)
signal charge_changed(value: float)
signal cast_started(distance_m: float)
signal nibble_happened
signal bite_started
signal bite_missed
signal fish_hooked(fish: FishDef)
signal fish_caught(fish: FishDef, size_cm: float, junk_name: String)
signal line_snapped
signal fish_escaped(reason: String)   # early / missed / give_up
signal tension_changed(value: float)
```

**注意 `fish_escaped` 带了个 `reason` 字符串**。一开始我只发了信号不带参数，结果 UI 只能笼统提示"鱼跑了"。
加上 reason 之后，就能分别提示"太急了，它被吓跑了"和"慢了半拍"，手感完全不同。

## 步骤 2：让随机可控

```gdscript
func setup(pool: Array[FishDef], rng_seed: int) -> void:
    fish_pool = pool
    _rng.seed = rng_seed
```

测试里传固定种子，就能断言"这一杆会出真鲷"。
游戏里传 `Time.get_ticks_usec()`，每次不一样。

**不要用全局 `randi()`**，那样没法复现 bug。

## 步骤 3：数值外置

`data/fish.json` 里每条鱼是这样的：

```json
{
  "id": "bluefin",
  "name": "蓝鳍小金枪",
  "rarity": 3,
  "size_min": 40,
  "size_max": 120,
  "weight": 6,
  "zones": ["reef", "deep"],
  "phases": ["dawn", "dusk"],
  "fight": "strong",
  "icon": "res://assets/fish/bluefin.png"
}
```

`GameData` 加载时做三件事：

1. 解析成 `FishDef` 对象（`RefCounted`，不是 `Resource`——见下面的坑）
2. 校验 `icon` 路径是否存在
3. 把错误攒在 `errors()` 里，等 `main.gd` 启动时统一报

```gdscript
func errors() -> Array[String]:
    return _errors
```

### 坑：别用 `Resource` 做数据类

我最开始把 `FishDef` 写成了 `Resource`（想着以后能在编辑器里可视化编辑）。
结果是：`--script` 模式下加载 `Resource` 需要资源数据库，headless 测试直接失败。

改成 `RefCounted` + JSON 后，测试环境零依赖。

## 步骤 4：概率过滤的两层

一杆能钓到什么，取决于三件事：时段、水域、鱼饵。

```gdscript
func _pick_fish() -> FishDef:
    var phase := _phase()          # 从 phase_provider 拿，默认 "noon"
    var candidates: Array[FishDef] = []
    var weights: Array[float] = []
    for f in fish_pool:
        if f.rarity == 0:          # 传说/杂物单独处理
            continue
        var w := float(f.weight)
        if f.phases.size() > 0 and not f.phases.has(phase):
            w *= 0.15              # 不在时段内：降到 15%，不是完全排除
        if not f.zones.has(_zone):
            w *= 0.2
        if w > 0.0:
            candidates.append(f)
            weights.append(w)
    ...
```

**关键决策：不在时段内的鱼不是"钓不到"，而是"概率降到 15%"。**
完全排除会让玩家觉得"这游戏鱼好少"，降权则保留惊喜感，又能让"黄金时刻"有实感。

## 步骤 5：拉扯期的张力模型

这是整个手感的核心，也是最容易被写成"随机扣血"的地方。

```gdscript
const REEL_RATE := 14.0           # 收线：张力 +14/s
const RELEASE_RATE := 22.0        # 放线：张力 -22/s
const TENSION_DECAY := 8.0        # 松手：自然回落 -8/s
const TENSION_SNAP := 95.0        # 到 95 断线
const REEL_SPEED := 3.2           # 收线 3.2 m/s
const SLACK_OUT_SPEED := 1.5      # 放线 1.5 m/s
```

三条规则：

1. **按住收线**：张力升、距离减
2. **松开**：张力降、距离不变（不是"放线"）
3. **鱼挣扎时**：额外加张力

```gdscript
if _struggling:
    tension += STRUGGLE_RATE
    fish_stamina -= STRUGGLE_STAMINA_DRAIN * dt
```

体力耗尽后挣扎衰减到 35%（`TIRED_FACTOR`），玩家会明显感觉"它没劲了"——
这个正反馈比任何血条都直观。

**为什么用 95 而不是 100 断线？** 因为要留出 HUD 的红区。
张力条到 95 就爆，红区画在 80–95，玩家看到进红区还有 0.2 秒反应时间。

## 步骤 6：把它测穿

因为是纯逻辑，测试可以这样写：

```gdscript
func _test_happy_path() -> void:
    var core := FishingCore.new()
    core.setup(pool, 1234)

    core.request_charge()
    for i in 60:
        core.tick(0.016)
    core.release_charge()          # 抛竿

    for i in 3000:
        core.tick(0.016)
        if core.state == FishingCore.State.BITE:
            core.strike()          # 咬钩瞬间提竿
            break

    # 收线到上鱼
    for i in 6000:
        core.set_reeling(core.tension < 70.0)
        core.tick(0.016)
        if core.state == FishingCore.State.IDLE:
            break
```

不需要场景、不需要窗口、不需要等真实时间——`tick(dt)` 是纯函数式推进。

这就是把 `dt` 作为参数传进去的好处：**测试可以 0.016 秒一步地"快进"整局游戏。**
