# 01 · 从设计文档到可玩骨架

> 目标：搭出一个"能走能看"的最小可玩骨架 —— 岛、人、相机、UI，30 行装配代码。
> 预计 20 分钟 · 前置：无

---

## 先做减法

新手最容易死在"我要先设计一个完美的架构"。这里反过来：**只留一个场景、一个装配脚本**，其余全部用代码 `new()` 出来。

好处很直接：

- `.tscn` 不会因为谁的编辑器版本不同而冲突
- 所有节点都在代码里，能一眼看清初始化顺序
- 想重构就改代码，不用在场景树里点来点去

代价也有：不能在编辑器里可视化调参。所以我留了 `data/*.json` 做数值外置，见第 02 篇。

---

## 步骤 1：三行 `main.tscn`

整个项目只有一个场景文件，里面只有一个挂脚本的根节点：

```
[gd_scene load_steps=2 format=3]
[ext_resource type="Script" path="res://scripts/main.gd" id="1"]
[node name="Main" type="Node3D"]
script = ExtResource("1")
```

就这些。世界、玩家、UI、音频，全在 `main.gd` 的 `_ready()` 里长出来。

---

## 步骤 2：三个 autoload，各管一件事

`project.godot`：

```ini
[autoload]
GameData="*res://scripts/game_data.gd"
SaveManager="*res://scripts/save_manager.gd"
ThemeManager="*res://scripts/theme_manager.gd"
```

分工是按**生命周期**切的，不是按功能：

| autoload | 生命周期 | 管什么 | 为什么必须是单例 |
|---|---|---|---|
| `GameData` | 进程级只读 | 读 `data/*.json`，抛 `errors()` 给启动检查 | 全是静态配置，谁都能读 |
| `SaveManager` | 进程级可写 | `user://` 存档、鱼谱、目标进度 | 多处读写，必须统一 flush 时机 |
| `ThemeManager` | 跟昼夜走 | 当前色板 + 广播 `theme_changed` | 换肤时要让所有 UI 同时刷新 |

**关键点**：Node 的 `_ready()` 是自底向上跑的，autoload 一定比主场景先 ready。
所以 `GameData` 的 JSON 在 `main.gd` 里已经可用，不需要 await。

启动自检就这么写：

```gdscript
func _ready() -> void:
    for e in GameData.errors():
        push_error(e)
```

`errors()` 返回的是"配置文件里引用了不存在的鱼 id"这类问题。数据驱动的项目一定要有这层，
否则错别字会一路静默到运行时才炸。

## 步骤 3：装配顺序是有讲究的

`main.gd` 里不是随便 `add_child`，顺序影响三件事：光照、UI 层次、信号连接。

```gdscript
func _ready() -> void:
    var refs := WorldBuilder.build(self)   # 1. 世界先建，返回需要被引用的节点

    # 2. 环境与光照（必须在世界之后，否则第一天是黑的）
    var env := Environment.new()
    ...
    var sun := DirectionalLight3D.new()
    add_child(sun)

    # 3. 玩家（相机在玩家身上，必须早于 UI）
    player = Player.new()
    player.position = refs["spawn"]
    add_child(player)

    # 4. HUD（CanvasLayer，晚加就在上面）
    hud = Hud.new()
    add_child(hud)

    # 5. 昼夜驱动器，把引用塞进去
    day_night = DayNightDriver.new()
    day_night.sun = sun
    day_night.environment = env
    ...
    add_child(day_night)
    day_night.apply()

    # 6. 钓鱼控制器（依赖 player + hud）
    fishing = FishingController.new()
    fishing.player = player
    fishing.hud = hud
    ...
```

### 两个真实的坑

**坑 1：信号要先连，再 `add_child`。**

```gdscript
fishing.bait_changed.connect(_on_bait_changed)
add_child(fishing)     # ← add_child 会立刻触发 _ready，_ready 里 emit 的信号就丢了
```

我第一次把 `connect` 写在 `add_child` 后面，结果鱼饵数量永远显示 0。

**坑 2：`refs` 字典是唯一的世界句柄。**

`WorldBuilder.build()` 返回的字典长这样：

```gdscript
{
    "spawn": Vector3,
    "water": MeshInstance3D,
    "dock": {"lamp": OmniLight3D, ...},
    "hut": {"window_light": ...},
    "fireflies": GPUParticles3D,
}
```

因为世界是纯代码建的，没有场景引用可用，只能靠返回值传递。加新东西就往这个字典里塞。

## 步骤 4：世界怎么"长"出来

`world_builder.gd` 全是 `static func`，不持有状态。核心是一个高度函数：

```gdscript
const ISLAND_RADIUS := 60.0
const SHORE_RADIUS := 46.0
const ISLAND_HEIGHT := 5.0

static func island_height(x: float, z: float) -> float:
    # 距圆心越远越低，46m 处归零，再往外是水下
```

这一个函数同时被三处用：

1. 生成地形网格（顶点高度）
2. 玩家的踩水限制（"不能往更深处走"）
3. 地表类型判定（沙 / 草 / 礁，影响移速）

**一个函数三处复用，是这类程序化地形最省事的做法。** 千万别各写一份，否则玩家会和地形错位。

## 步骤 5：玩家与相机

第三人称用 `SpringArm3D`，它在相机和目标之间做碰撞检测，撞墙会自动拉近：

```gdscript
_arm = SpringArm3D.new()
_arm.spring_length = 4.0
_arm.collision_mask = 1        # 只和地形碰
_arm.margin = 0.25

_camera = Camera3D.new()
_camera.fov = 60.0
_arm.add_child(_camera)
```

鼠标控制是"转 rig 的 yaw + 转 arm 的 pitch"，不是直接转相机：

```gdscript
_rig.rotation.y -= m.relative.x * 0.0032
_arm.rotation.x = clampf(_arm.rotation.x - m.relative.y * 0.0028, -1.15, 0.25)
```

为什么分开？因为移动方向要用 `_rig` 的水平朝向算，相机俯仰不能影响走路方向。
这个结构后面接动画状态机（第 09 篇）时不用改。

## 验收

- 按 WASD 能在岛上走动，镜头跟随，鼠标能转视角
- 走到海岸线不会继续往深水走
- 屏幕上有 HUD（此时可能是空壳）

```bash
godot --path . --rendering-driver opengl3
```
