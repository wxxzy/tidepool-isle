# 04 · 真实渲染截图验证法

> 目标：不靠肉眼、不靠"我看着还行"，用程序化截图 + 断言判断 UI 是否真的对了。
> 预计 25 分钟 · 前置：第 03 篇

---

## 起因

上一版我信心满满地说"UI 做好了"。用户打开 Godot 跑了一遍，回我一句：

> 我通过 Godot 编辑器运行打开和你的 exe 打开，界面都没有变化啊，你自己测试再说做好了。

一查，四个问题全是肉眼能看出来、但"编译通过"完全发现不了的：

| # | 问题 | 根因 |
|---|---|---|
| 1 | 图标全是方块 | 用了 emoji，导出包字体不含字形 |
| 2 | 所有面板一个颜色 | 换肤只在 setup 时算一次，且色值硬编码 |
| 3 | 鱼谱面板撑出屏幕 | 512px 插画画进 188px 卡片，把 Grid 顶爆 |
| 4 | 夜晚地面比天空亮 | 环境光写了 `maxf(0.25, ...)`，下限锁死 |

这四条没有一个能被"跑通不报错"测出来。**所以验证手段必须变成像素。**

## 步骤 1：截图探针不是测试，是"体检"

`tests/visual_probe.gd` 是一个 `SceneTree` 脚本，做三件事：

1. 用 `load("res://scenes/main.tscn")` 实例化主场景
2. 通过状态驱动，把游戏摆到指定画面（蓄力 / 张力 / 结算 / 夜晚 / 鱼谱）
3. 每个状态 `get_viewport().get_texture().get_image().save_png()`

```gdscript
func _initialize() -> void:
    _scene = (load("res://scenes/main.tscn") as PackedScene).instantiate()
    root.add_child(_scene)

func _process(_dt: float) -> bool:
    _f += 1
    match _f:
        30:  _shot("01_day.png")
        60:  _drive_charge(); _shot("02_charge.png")
        ...
```

**必须带 `--rendering-driver opengl3`，不能加 `--headless`。**
headless 用的是 Dummy 渲染器，`get_image()` 拿到的是空图。

```bash
godot --path . --rendering-driver opengl3 --audio-driver Dummy \
      --resolution 1280x720 --script tests/visual_probe.gd
```

输出落在 `user://probe/`，Windows 上是：

```
C:\Users\<你>\AppData\Roaming\Godot\app_userdata\Tidepool Isle 潮汐小岛\probe\
```

## 步骤 2：探针要覆盖"状态"，不是"页面"

我一开始每个界面截一张，结果漏掉了最关键的**中间态**（蓄力中的张力条、咬钩瞬间的提示）。

现在按状态切：

| 截图 | 怎么摆出来的 |
|---|---|
| `01_day.png` | 默认，白天 |
| `02_charge.png` | 调 `fishing.core.request_charge()` 并 tick 几十帧 |
| `03_tension_golden.png` | 进 FIGHT 态，手动把 `tension` 拉到 78 |
| `04_result.png` | 直接调 `hud.show_result(...)` |
| `05_night.png` | `day_night.hour = 21.0` 后 `apply()` |
| `06_dex.png` | `fish_dex.toggle()` |

**技巧：直接调内部方法，不要模拟输入。**
模拟鼠标要处理指针锁定、DPI、窗口焦点，脆得很；直接调状态函数稳定得多。

## 步骤 3：把"看"变成"断言"

截图只解决了"我能看到"，不解决"下次改坏了没人发现"。所以把四个 bug 全部写成断言：

```gdscript
func _test_ui_layout() -> void:
    var vp := get_viewport().get_visible_rect().size

    # bug 2：目标卡高度贴合内容（之前固定 96px，底部一大片空白）
    var gc: PanelContainer = _hud.get("_goal_card")
    _check(gc != null and gc.size.y > 40.0 and gc.size.y <= 120.0,
        "今日目标卡高度贴合内容（%.0fpx）" % gc.size.y)

    # bug 3：鱼谱面板必须完整落在视口内
    var r := panel.get_global_rect()
    _check(r.position.x >= -1.0 and r.end.x <= vp.x + 1.0
        and r.position.y >= -1.0 and r.end.y <= vp.y + 1.0,
        "鱼谱面板完整落在视口内")

    # 关键：尺寸上限要独立断言
    # headless 视口是 1280×1280，只靠视口判断抓不到 720p 下的纵向溢出
    _check(r.size.x <= 1000.0 and r.size.y <= 640.0,
        "鱼谱面板尺寸在设计分辨率内")

    # bug 3 根因：TextureRect 没设 EXPAND_IGNORE_SIZE
    for c in grid.get_children():
        for g in c.find_children("*", "TextureRect", true, false):
            if g.expand_mode != TextureRect.EXPAND_IGNORE_SIZE:
                tex_ok = false
    _check(tex_ok, "鱼插画 TextureRect 使用 EXPAND_IGNORE_SIZE")

    # bug 4：夜间环境光必须被压暗
    var amb := float(GameData.daycycle.phase_at(21.0).get("ambient", 1.0))
    _check(amb <= 0.15, "夜间环境光已压暗（ambient=%.2f）" % amb)
```

### `EXPAND_IGNORE_SIZE` 是什么

`TextureRect` 的默认 `expand_mode` 是 `EXPAND_KEEP_SIZE`，也就是**控件最小尺寸 = 贴图尺寸**。
一张 512×512 的插画塞进卡片，卡片就被撑到 512——GridContainer 一算，整个面板炸了。

改成 `EXPAND_IGNORE_SIZE`，控件尺寸由布局决定，贴图只负责填充。

这个坑值得单独记一条：**任何"图片把布局顶歪"的问题，先看 `expand_mode`。**

---

## 步骤 4：headless 的视口陷阱

断言里我特意加了尺寸上限，因为：

- headless 模式视口是 `1280×1280`（正方形）
- 真机 720p 是 `1280×720`

只判"在视口内"，1280 高度能过，720 就溢出。所以**上限必须写死成设计值**（1000×640），
不能只依赖 `get_visible_rect()`。

## 步骤 5：模型也要单独体检

角色和 3D 资产不能靠 UI 探针，单独写：

- `tests/character_probe.gd` —— 背/正/侧/走路/持竿/特写 6 张
- `tests/model_views.gd` —— 任意 GLB 的 0/90/180/270 四向检视
- `tests/rig_probe.gd` —— 绑定后的 4 个姿势 + 侧视 5 帧步态
- `tests/fish_probe.gd` —— 水面鱼群 / 鱼特写 / 俯视 / 玩家岸边

`model_views.gd` 特别有用：换任何新模型，先跑一遍这个，

```bash
godot --path . --rendering-driver opengl3 --audio-driver Dummy \
      --resolution 1100x620 --script tests/model_views.gd -- \
      "res://assets/models/hero.glb" 2.6
```

**一张图就能看出朝向错没错、有没有多余几何、贴图有没有坏。** 第 06 篇那个"模型躺下"的问题就是靠它定位的。

## 步骤 6：导出包也要自检

上面全是编辑器里跑的。导出的 exe 是另一个世界（资源打包方式不同，见第 07 篇）。

所以 `main.gd` 里加了一个开关：

```gdscript
func _parse_shot_args() -> void:
    for a in OS.get_cmdline_user_args():
        if a.begins_with("--shot="):
            _shot_path = a.substr(7)
        elif a.begins_with("--shot-frames="):
            _shot_frames = int(a.substr(14))

func _process(_dt: float) -> void:
    if _shot_path == "":
        return
    _shot_frames -= 1
    if _shot_frames > 0:
        return
    var img := get_viewport().get_texture().get_image()
    img.save_png(_shot_path)
    print("SHOT_SAVED ", _shot_path)
    get_tree().quit()
```

用法：

```bash
TidepoolIsle.exe --rendering-driver opengl3 --audio-driver Dummy \
  -- --shot="C:\tmp\exe_shot.png" --shot-frames=120
```

注意 `--` 之后才是游戏自己的参数（Godot 的 `get_cmdline_user_args()` 只读这段）。

**这一步救了命**：第 07 篇那个"导出的 exe 里角色退回方块模型"的问题，
编辑器里怎么测都是好的，只有 exe 截图才能暴露。
