## 为什么分两套测试

| | 单元测试 | 集成测试 |
|---|---|---|
| 入口 | `--script tests/run_tests.gd` | 跑 `tests/integration_scene.tscn` |
| autoload 可用？ | **❌ 不可用** | ✅ 可用 |
| 数量 | 129 | 37 |
| 测什么 | JSON、状态机、概率、色板、资源存在性 | 真实节点装配、UI 布局、角色骨架、存档 |
| 速度 | 2 秒 | 8 秒 |

### 关键机制：`--script` 模式下 autoload 不参与编译

这是 Godot 一个反直觉的行为：用 `--script` 跑一个 `SceneTree` 脚本时，
**autoload 的单例名（`GameData`）在脚本编译阶段是未定义的**。

所以 `run_tests.gd` 里**不能**写 `GameData.fish_defs`——会直接编译失败。
必须绕开：

```gdscript
func _load_json(path: String) -> Dictionary:
    var text := FileAccess.get_file_as_string(path)
    return JSON.parse_string(text) if text != "" else {}

func _load_pool() -> Array[FishDef]:
    var data := _load_json("res://data/fish.json")
    for fd in data.get("fish", []):
        ...
```

**读文件而不是读单例**。同理，主场景实例化也不能放在 `--script` 里测，
所以我把它挪到集成场景：

```gdscript
# tests/integration_scene.tscn  → Node + integration_test.gd
func _ready() -> void:
    await _build_world()          # 真实 new 出 Player / FishingController / Hud
    await _test_full_fishing_cycle()
    await _test_ui_layout()
    _test_character_rig()
    _test_save_manager()
```

跑法：

```bash
godot --headless --path . res://tests/integration_scene.tscn
```

## 怎么加一条测试

`_check()` 是唯一入口，两个参数：条件、描述。

```gdscript
func _check(cond: bool, msg: String) -> void:
    _count += 1
    if cond:
        print("  ok - %s" % msg)
    else:
        _fails += 1
        printerr("FAIL - %s" % msg)
```

**描述里一定要带实测值**，不然失败时你还得回去加 print：

```gdscript
_check(gc.size.y > 40.0 and gc.size.y <= 120.0,
    "今日目标卡高度贴合内容（%.0fpx）" % gc.size.y)
```

好的断言长这样：`FAIL - 今日目标卡高度贴合内容（244px）` —— 一眼知道差多少。

## 四类断言，各有各的写法

### 1. 数据类

```gdscript
_check(GameData.fish_defs.size() == 13, "加载 13 鱼种")
for f in pool:
    if f.icon != "":
        _check(ResourceLoader.exists(f.icon), "鱼插画存在: %s" % f.icon)
```

**校验数据引用的资源真的存在**——这条抓住过好几次改文件名忘了改 JSON。

### 2. 资源类

```gdscript
var rigged := "res://assets/models/hero_rigged.glb"
_check(FileAccess.file_exists(rigged), "绑骨版主角存在")
var rt := ModelLib.template(rigged)
_check(ModelLib.has_skin(rt), "含骨骼")
var ap := ModelLib.find_anim_player(rt)
_check(ap.get_animation_list().has("walk"), "含 walk 动画")
```

不只是"文件在"，还要"结构对"。文件在但没骨骼，一样跑不起来。

### 3. 布局类

见第 04 篇。要点：**尺寸上限写死成设计值**，别只信视口。

### 4. 行为类

```gdscript
p.set("frozen", false)
for i in 4:
    p.call("_animate", 0.05, 3.2)
_check(str(p.get("_anim_name")) == "walk", "移动时切换到 walk")
```

不要模拟输入事件（指针锁定、焦点、DPI 全是坑），**直接调内部方法**。

## 发布

### 两个预设

`export_presets.cfg` 里配了 Web 和 Windows Desktop。命令行导出：

```bash
godot --headless --path . --export-release "Windows Desktop" "../outputs/TidepoolIsle.exe"
godot --headless --path . --export-release "Web" "../outputs/tidepool_isle_web/index.html"
```

### Web 的模板坑

Godot 4.7 默认找 `web_nothreads_*` 模板，但很多人只装了带线程的 `web_*`。
所以预设里显式指定：

```ini
custom_template/release="C:/Users/<你>/AppData/Roaming/Godot/export_templates/4.7.1.stable/web_release.zip"
```

换机器时要么装全模板，要么清空这两个字段让它自己找。

### 导出自检（必做）

```bash
./TidepoolIsle.exe --rendering-driver opengl3 --audio-driver Dummy \
  -- --shot="./shot.png" --shot-frames=120
```

**每次发版都截一张。** 编辑器里正常、导出后降级的问题（第 07 篇），只有这一步能抓到。

## 已知边界（诚实清单）

这些不是 bug，是当前设计的天花板，写出来供你判断要不要继续投入：

| 项 | 现状 | 想更好要做什么 |
|---|---|---|
| 主角动作 | 只有 idle / walk / hold 三段，无手指、无表情骨、无跑跳 | 走混元 `hy-3d-rigging`（要 A-pose 无道具模型 + 公网 URL），或 Blender 手绑 + 动捕重定向 |
| 3D 鱼种 | 5 / 13，剩余 7 条因积分不足未生成 | 充值 210 积分，跑 `spec_remaining.json` |
| 导出包退出 | Windows 导出包退出时偶发段错误（exit 139），画面与数据不受影响；开发版正常 | 未定位，怀疑引擎收尾竞态，不影响游玩 |
| 水下可见度 | 鱼在水面下 0.25–0.5m，透过水面能看到但偏淡 | 降低水面 alpha 或给鱼加自发光，需要美术判断 |
| 音效 | 程序化合成，不是实录 | 换成真实采样 |

**把边界写进 README**，比假装没有强。用户看到"这游戏没有跑跳"，和"这游戏跑跳坏了"，是两种完全不同的感受。

## 结语

回头看，这个项目 90% 的时间花在四件事上：

1. **让资产能进得来**（接口、限流、后处理、坐标）
2. **让资产能进得对**（导出包 remap、骨骼、动画状态）
3. **让错误能被看见**（截图探针、exe 自检）
4. **让下次不会再错**（把每个坑写成断言）

代码本身反而是最不缺的。

如果你只从这套教程里带走一句话，我希望是这句：

> **不要相信"编译通过"，也不要用肉眼看完之后说"好了"。截图 + 断言，才叫完成。**
